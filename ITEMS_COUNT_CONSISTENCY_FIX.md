# 🔧 Исправление несоответствия количества изделий

## ❌ **Проблема:**

Пользователь сообщил:

```
когда заказы загрузились то не верно показывает количество изделий, так как после загрузки оно меняется и пересчитывается на верное
```

**Проблема:** Количество изделий показывалось неправильно изначально и менялось после загрузки материалов:

- **До загрузки:** `itemsWithMaterial` (неправильное значение, часто 0)
- **После загрузки:** `filteredItemsCount` (правильное значение)

## 🔍 **Анализ проблемы:**

### **Логика была неправильной:**

```javascript
// БЫЛО:
${needsMaterialJoins ? 'COUNT(oi.ORDERITEMSID) as ITEMS_WITH_MATERIAL' : '0 as ITEMS_WITH_MATERIAL'}
```

**Проблема:** Когда нет фильтров по материалам (`needsMaterialJoins = false`):

- Показывалось `0 as ITEMS_WITH_MATERIAL`
- Это означало, что все заказы показывали "0 изделий с искомым материалом"
- После загрузки материалов показывалось правильное количество

### **Пример проблемы:**

```
Заказ 1: "0 изделий с искомым материалом"  ← Неправильно!
Заказ 2: "0 изделий с искомым материалом"  ← Неправильно!
Заказ 3: "0 изделий с искомым материалом"  ← Неправильно!

После загрузки материалов:
Заказ 1: "5 изделий с искомым материалом"  ← Правильно!
Заказ 2: "3 изделия с искомым материалом"  ← Правильно!
Заказ 3: "7 изделий с искомым материалом"  ← Правильно!
```

## 🔧 **Решение:**

### **Исправлено в `server/AW/controllers/statisticsController_new.js`:**

```javascript
// БЫЛО (неправильно):
FROM ORDERS o
${needsMaterialJoins ? 'JOIN ORDERITEMS oi ON ...' : ''}  // JOIN только при нужде
${needsMaterialJoins ? 'GROUP BY ...' : ''}  // GROUP BY только при нужде

// СТАЛО (правильно):
FROM ORDERS o
LEFT JOIN ORDERITEMS oi ON o.ORDERID = oi.ORDERID  // Всегда JOIN
${needsMaterialJoins ? 'LEFT JOIN MODELS md ON ...' : ''}  // Дополнительные JOIN'ы только при нужде
GROUP BY o.ORDERID, o.ORDERNO, o.DATECREATED, o.ORDERSTATUS  // Всегда GROUP BY
```

### **Ключевые изменения:**

1. **Всегда JOIN с ORDERITEMS:**

   ```sql
   LEFT JOIN ORDERITEMS oi ON o.ORDERID = oi.ORDERID
   ```

2. **Всегда COUNT изделий:**

   ```sql
   COUNT(oi.ORDERITEMSID) as ITEMS_WITH_MATERIAL
   ```

3. **Всегда GROUP BY:**
   ```sql
   GROUP BY o.ORDERID, o.ORDERNO, o.DATECREATED, o.ORDERSTATUS
   ```

## 📊 **Сравнение запросов:**

### **Было (неправильно):**

```sql
-- Без фильтров по материалам:
SELECT
  o.ORDERID,
  o.ORDERNO,
  o.DATECREATED,
  o.ORDERSTATUS,
  0 as ITEMS_WITH_MATERIAL  -- ← Неправильно!
FROM ORDERS o
WHERE o.DELETED = 0
-- Нет JOIN'ов и GROUP BY
```

### **Стало (правильно):**

```sql
-- Без фильтров по материалам:
SELECT
  o.ORDERID,
  o.ORDERNO,
  o.DATECREATED,
  o.ORDERSTATUS,
  COUNT(oi.ORDERITEMSID) as ITEMS_WITH_MATERIAL  -- ← Правильно!
FROM ORDERS o
LEFT JOIN ORDERITEMS oi ON o.ORDERID = oi.ORDERID  -- ← Всегда JOIN
WHERE o.DELETED = 0
GROUP BY o.ORDERID, o.ORDERNO, o.DATECREATED, o.ORDERSTATUS  -- ← Всегда GROUP BY
```

## 🎯 **Логика исправления:**

### **Теперь всегда:**

1. ✅ **JOIN с ORDERITEMS** - для подсчета изделий
2. ✅ **COUNT(oi.ORDERITEMSID)** - правильный подсчет изделий
3. ✅ **GROUP BY** - для агрегатных функций

### **Результат:**

- **Без фильтров по материалам:** Показывается общее количество изделий в заказе
- **С фильтрами по материалам:** Показывается количество изделий с искомым материалом

## ✅ **Преимущества исправления:**

1. ✅ **Консистентность** - количество изделий не меняется после загрузки
