# Фоновые процессы (заказы 1С, сверка, рекламации): план переноса для мобильного приложения

Документ описывает **серверные cron/фоновые ветки** из `server/telegram_dealer_bot`, которые **нельзя потерять** при переносе функционала в POZ. Клиент не заменяет эти процессы; он только **получает уведомления** и **отправляет ответы** (подтверждение даты, оценка рекламации и т.д.).

**Принцип:** интеграция с 1С остаётся на **node.js**; мобильное приложение ходит в **`server/mobile_app`**.

---

## 1) Заказы 1С для дилеров (`V0O`)

| | |
|--|--|
| **Код** | `server/telegram_dealer_bot/queryLines/orders1c/orders1c.js` — `getOrders1C('V0O', …)` |
| **Ответы дилера** | `server/telegram_dealer_bot/queryLines/orders1c/orderHandlers.js` |
| **Смысл** | Периодически загружаются заказы из 1С, фильтруются, пишутся в БД; дилеру уходят кнопки **«Подтвердить дату»** / **«Перенести дату»**. |
| **Далее** | Ответы обрабатываются и уходят как **напоминания МПП** (`createReminder` / смежная логика). |
| **Особенность** | Контроль **просрочки ответа после 12:00** (late response). |

**Перенос:** cron остаётся на сервере (`modules/shared/schedulers` в `mobile_app`). Вместо Telegram — **push / in-app inbox** в POZ; те же идентификаторы заказов и действия API для подтверждения/переноса.

---

## 2) Закрытые рекламации и рейтинг (`V6Z`, `V0N`)

| | |
|--|--|
| **Код** | `server/telegram_dealer_bot/helpers/api.js` — `getReclamationClose`, обработка результатов, `sendReclamationRating`, cron по `V6Z` |
| **Смысл** | Поиск закрытых рекламаций, рассылка в чаты, сбор **оценки**; отправка оценки в 1С **`V0N{claim}Q{1..5}`**. |

**Перенос:** фоновые джобы на `mobile_app`; клиент показывает карточку «оцените закрытие» и отправляет оценку на API, сервер вызывает тот же протокол, что `sendReclamationRating`.

Подробности сценариев рекламации — в **`Рекламация_полный_план_переноса_в_mobile_app.md`**.

---

## 3) Ежедневная сверка заказов (`V0Z`)

| | |
|--|--|
| **Код** | `server/telegram_dealer_bot/helpers/api.js` — `getReconciliationOrders('V0Z')`, группировка, рассылка |
| **Смысл** | Сверка заказов и уведомления дилерам по расписанию. |

**Перенос:** аналогично п. 1 — серверный cron + push/лента. Логика сверки заказов по запросу пользователя — в **`Сверка_полный_план_переноса_в_mobile_app.md`** (в т.ч. раздел cron `V0Z`).

---

## 4) Общие требования

- Не дублировать TCP 1С в приложении.
- Сохранить **эквивалентные входы/выходы** и таймауты при выносе функций в `oneCClient` / общий шлюз.
- Идемпотентность рассылок и дедупликация push при миграции с Telegram.

---

## 5) Чеклист

- [ ] `V0O`: загрузка, БД, действия пользователя, напоминания МПП, late response.
- [ ] `V6Z` / рейтинг: не разрывать цепочку до `V0N`.
- [ ] `V0Z`: ежедневная рассылка и отображение в POZ.
- [ ] Документация API для каждого пользовательского действия, заменяющего callback Telegram.
