# Исправление ошибок "missed execution" в node-cron

## 🔍 Анализ проблемы

### Ошибки в логах:

```
[2025-09-13T06:00:05.327Z] [NODE-CRON] [WARN] missed execution at Sat Sep 13 2025 10:00:00 GMT+0400 (GMT+04:00)! Possible blocking IO or high CPU user at the same process used by node-cron.
[2025-09-13T06:35:05.363Z] [NODE-CRON] [WARN] missed execution at Sat Sep 13 2025 10:35:00 GMT+0400 (GMT+04:00)! Possible blocking IO or high CPU user at the same process used by node-cron.
[2025-09-13T07:00:03.582Z] [NODE-CRON] [WARN] missed execution at Sat Sep 13 2025 11:00:00 GMT+0400 (GMT+04:00)! Possible blocking IO or high CPU user at the same process used by node-cron.
```

### Причины ошибок:

1. **Блокирующие сетевые операции**: Функции `getReclamationClose`, `getReconciliationOrders` и `getOrders1C` использовали синхронные сетевые операции с `net.Socket`, которые блокировали event loop Node.js

2. **Длительные таймауты**: Слишком большие таймауты (30 секунд на ответ, 10 секунд на подключение) приводили к длительному блокированию

3. **Неправильная обработка ресурсов**: Отсутствие флага `isResolved` приводило к множественным вызовам resolve/reject

4. **Отсутствие защиты от зависания**: CronManager не имел таймаута на выполнение задач

## 🛠️ Внесенные исправления

### 1. Улучшение сетевых функций

#### В `getReclamationClose` (helpers/api.js):

- ✅ Уменьшены таймауты: подключение 5с → 5с, ответ 30с → 15с
- ✅ Добавлен флаг `isResolved` для предотвращения множественных вызовов
- ✅ Улучшена очистка ресурсов
- ✅ Добавлен общий таймаут сокета 20 секунд

#### В `getReconciliationOrders` (helpers/api.js):

- ✅ Аналогичные улучшения как в `getReclamationClose`
- ✅ Уменьшены таймауты для быстрого завершения

#### В `getOrders1C` (queryLines/orders1c/orders1c.js):

- ✅ Полностью переписана логика с улучшенной обработкой ошибок
- ✅ Добавлены таймауты и флаг `isResolved`

### 2. Улучшение CronManager

#### В `cronManager.js`:

- ✅ Добавлен таймаут выполнения задач (4 минуты)
- ✅ Улучшена защита от зависших задач
- ✅ Более агрессивная очистка ресурсов

### 3. Уменьшение таймаутов cron задач

#### В cron задачах:

- ✅ Таймаут задач уменьшен с 5 минут до 2 минут
- ✅ Более быстрое завершение при проблемах с сетью

### Новые таймауты:

- **Подключение**: 5 секунд
- **Ответ сервера**: 15 секунд

- Флаг `isResolved` предотвращает множественные вызовы
- Автоматическая очистка таймаутов
- Принудительное закрытие сокетов
- Мониторинг зависших задач

```bash

```

Проверьте логи на отсутствие ошибок "missed execution":

