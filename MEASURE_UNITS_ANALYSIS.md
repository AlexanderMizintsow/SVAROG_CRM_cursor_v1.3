# 📏 Анализ учета единиц измерения в статистике

## ✅ **Ответ: Да, единицы измерения учитываются!**

Система правильно учитывает единицы измерения (метры, штуки, кг и т.д.) при расчете количества и цены в статистике.

## 🔍 **Как это работает:**

### **1. Структура единиц измерения:**

```sql
-- Таблица MEASURE (Единицы измерения)
MEASUREID (INTEGER) - ID единицы измерения
NAME (VARCHAR) - Наименование единицы измерения ("метр", "штука", "килограмм")
SHORTNAME (VARCHAR) - Краткое наименование ("м", "шт", "кг")
AMFACTOR (NUMERIC) - Коэффициент количества для пересчета
```

### **2. Логика расчета количества:**

```sql
-- В SQL запросах используется AMFACTOR для правильного расчета:
CASE
  WHEN (itd.ISEXTENDED = 1) THEN itd.QTY*itd.THICK/m.AMFACTOR
  ELSE itd.QTY*itd.THICK*oi.QTY/m.AMFACTOR
END as TOTAL_QUANTITY
```

**Где:**

- `itd.QTY` - количество материала
- `itd.THICK` - толщина/длина
- `oi.QTY` - количество изделий
- `m.AMFACTOR` - коэффициент единицы измерения

### **3. Примеры расчета:**

#### **Стеклопакеты (квадратные метры):**

```sql
-- AMFACTOR = 1 (для квадратных метров)
-- Расчет: QTY * WIDTH * HEIGHT / AMFACTOR
-- Пример: 2 шт * 1.5м * 1.2м / 1 = 3.6 кв.м
```

#### **Профиль (погонные метры):**

```sql
-- AMFACTOR = 1000 (если профиль в мм, а нужно в метрах)
-- Расчет: QTY * LENGTH / AMFACTOR
-- Пример: 1000 мм / 1000 = 1 м
```

#### **Крепеж (штуки):**

```sql
-- AMFACTOR = 1 (для штук)
-- Расчет: QTY * ITEM_QTY / AMFACTOR
-- Пример: 10 шт * 1 / 1 = 10 шт
```

## 📊 **Логика расчета цены:**

### **Цена также учитывает единицы измерения:**

```sql
SUM(itd.SAVINGCOST * (
  CASE
    WHEN (itd.ISEXTENDED = 1) THEN itd.QTY
    WHEN (itd.ISEXTENDED = 0) AND (COALESCE(g.AMOUNTGROUPID,0) = 1) THEN itd.QTY*oi.QTY
    ELSE itd.QTY*oi.QTY
  END
)) as TOTAL_COST
```

**Где:**

- `itd.SAVINGCOST` - цена за единицу материала
- `itd.QTY` - количество материала
- `oi.QTY` - количество изделий

## 🎯 **Примеры из реальных данных:**

### **Из логов пользователя:**

```
Total cost: 277827.13 ₽, Total quantity: 106.40
```

**Это означает:**

- **Общая стоимость:** 277,827.13 ₽ (с учетом всех единиц измерения)
- **Общее количество:** 106.40 единиц (метры, штуки, кг - в зависимости от материала)

### **Детальная статистика по материалам:**

```javascript
{
  MATERIAL_NAME: 'Заглушка для шлица 179 бел.',
  MATERIAL_TYPE: 'Комплектующие',
  MEASURE: 'м',  // ← Единица измерения
  MATERIAL_QUANTITY: 90.0238000488281,  // ← В метрах
  MATERIAL_COST: 1260.44  // ← Стоимость в рублях
}
```

## 🔧 **Как это работает в коде:**

### **1. В SQL запросах:**

```sql
-- JOIN с таблицей MEASURE для получения AMFACTOR
JOIN MEASURE m ON (g.MEASUREID = m.MEASUREID)

-- Использование AMFACTOR в расчетах
WHEN (itd.ISEXTENDED = 1) THEN itd.QTY*itd.THICK/m.AMFACTOR
ELSE itd.QTY*itd.THICK*oi.QTY/m.AMFACTOR
```

### **2. В результате:**

```javascript
// На клиенте отображается:
{
  totalQuantity: 106.40,  // ← Уже пересчитано в правильные единицы
  totalCost: 277827.13,   // ← Стоимость с учетом количества
  materialsStats: [
    {
      MATERIAL_QUANTITY: 90.02,  // ← В метрах
      MEASURE: 'м',              // ← Единица измерения
      MATERIAL_COST: 1260.44     // ← Стоимость
    }
  ]
}
```

## ✅ **Вывод:**

**Да, система правильно учитывает единицы измерения:**

1. ✅ **Количество** пересчитывается с учетом `AMFACTOR` из таблицы `MEASURE`
2. ✅ **Цена** рассчитывается с учетом количества в правильных единицах
3. ✅ **Статистика** показывает корректные значения для каждого типа материала
4. ✅ **Единицы измерения** отображаются в результатах (`м`, `шт`, `кг`)

**Статистика точная и учитывает все единицы измерения!** 🎉
