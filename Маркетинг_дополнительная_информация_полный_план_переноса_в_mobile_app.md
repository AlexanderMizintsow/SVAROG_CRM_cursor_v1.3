# Маркетинг / дополнительная информация: полный план переноса в мобильное приложение

Документ фиксирует раздел маркетинговых материалов из **`server/telegram_dealer_bot/queryLines/marketingInfo/marketingInfo.js`** для переноса в `apk/POZ` + `server/mobile_app`.

**Интеграция с 1С:** нет. Источники — **PostgreSQL** (`marketing_*`) и файлы **`uploads/marketing/*`**. Админка и REST для маркетинга также есть в **`telegram_dealer_bot`** (`controllers/marketingController.js`, маршруты `/api/marketing/...` в `index.js`).

---

## 1) Источники текущей логики

| Назначение | Файл |
|------------|------|
| Меню категорий, кампаний, деталей, вложения | `server/telegram_dealer_bot/queryLines/marketingInfo/marketingInfo.js` |
| CRUD маркетинга (админы) | `server/telegram_dealer_bot/controllers/marketingController.js` |
| Подключение роутов | `server/telegram_dealer_bot/index.js` |

---

## 2) Логика для пользователя (смысл)

1. По **`chat_id`** находится **`company_id`** в **`user_company_tg_bot`**.
2. Из **`company_addresses`** собираются **города** компании.
3. Выбираются **категории**, в которых есть **кампании**:
   - статус **active**;
   - период: **unlimited** / **date** (отправка в конкретный день) / **period** (диапазон дат);
   - фильтр по компании: кампания без привязки ко всем **или** явно привязана к текущей компании;
   - фильтр по локации: кампания без локаций **или** локация совпадает с городами из адресов компании (через **`marketing_locations`**).
4. Пользователь проходит: **категория → кампания → детали** (текст, изображения, вложения с диска).

---

## 3) Перенос в мобильное приложение

| Тема | Рекомендация |
|------|----------------|
| Модуль | Отдельный **контент-модуль**: список категорий, список кампаний с пагинацией, экран детали. |
| API | Эндпоинты в `mobile_app`: например `GET /mobile/marketing/categories`, `.../campaigns`, `.../campaigns/:id` с той же фильтрацией, что в `showMarketingMenu` / дочерних запросах. |
| Файлы | Отдача вложений через защищённые URL (токен сессии, срок жизни), без прямого доступа к чужим компаниям. |
| Права | Только авторизованный дилер; **company_id** из сессии, не из произвольного параметра клиента. |
| Приоритет | **P3**. |

---

## 4) Паритет и тесты

- [ ] Кампания, доступная в TG для компании A, видна в POZ для того же пользователя A; для компании B — нет.
- [ ] Уважается период активности и «дата однодневной» кампании.
- [ ] Города без записи в `marketing_locations` ведут себя как в SQL-ветке (только кампании без привязки к локациям).
- [ ] Большие вложения: таймауты, возобновление загрузки — по стандартам POZ.
