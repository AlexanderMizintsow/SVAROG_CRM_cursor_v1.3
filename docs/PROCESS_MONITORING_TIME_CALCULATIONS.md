# Расчёт времени в Мониторинге процессов

## Логика: без суммирования по экземплярам

Время **не суммируется** по всем экземплярам процесса. Для каждого этапа показываются:
- **Среднее** — типичное время при одном проходе
- **Макс.** — максимальное время за один проход

Цель: понять, какой этап занимает больше всего времени при каждом выполнении процесса.

---

## Показатели по этапам

### Этап (ср. / макс.)

Время нахождения в узле: от `entered_at` до выхода или следующего шага.

### Задачи БП (ср. / макс.)

Для каждой задачи: `COALESCE(completed_at, NOW()) - created_at`.
- **Ср.** — среднее по задачам этапа
- **Макс.** — максимальное время одной задачи

### Проекты (ср. / макс.)

Время от создания проекта до последней активности (чат, история).
- **Ср.** / **Макс.** — по проектам этапа

### Задачи в проектах (ср. / макс.)

Аналогично задачам БП — время каждой задачи внутри проектов этапа.

### Ожидание почты (ср. / макс.)

Интервалы от `sent_at` до `reply_received_at` по проектам этапа.

---

## Ср. время процесса (целиком)

От **старта до завершения** каждого экземпляра: `COALESCE(finished_at, NOW()) - started_at`. Ср. и макс. по всем экземплярам за период. Не сумма по этапам.

## Узкое место

Этап с **наибольшим средним временем** (сумма ср. по этапу, задачам, проектам, почте). При улучшении этапа результат обновится — узкое место может перейти на другой этап.
