# Руководство по оптимизации поиска материалов

## Обзор оптимизаций

Система поиска материалов была полностью переработана для значительного улучшения производительности. Вместо одного сложного запроса с множественными JOIN'ами, теперь используется поэтапная загрузка данных.

## Архитектура решения

### 1. Поэтапная загрузка данных

**Проблема:** Один сложный запрос с множественными JOIN'ами выполнялся очень долго (5+ секунд).

**Решение:** Разделение на три этапа:

1. **Быстрая статистика** - подсчет общих результатов без деталей
2. **Список заказов** - получение базовой информации о заказах с пагинацией
3. **Детали заказа** - загрузка материалов только при раскрытии заказа

### 2. Новые методы API

#### `getSearchSummary(filters)`

- **Назначение:** Быстрый подсчет общей статистики
- **Время выполнения:** < 1 секунды
- **Возвращает:** Общее количество заказов, изделий, материалов, количество и стоимость

#### `getOrdersList(filters)`

- **Назначение:** Получение списка заказов с базовой информацией
- **Время выполнения:** < 2 секунды
- **Возвращает:** Список заказов с пагинацией (по 50 заказов)

#### `getOrderDetails(orderId, filters)`

- **Назначение:** Детальная информация по конкретному заказу
- **Время выполнения:** < 1 секунды
- **Возвращает:** Полную информацию о материалах в заказе

### 3. Оптимизированные SQL запросы

#### Основной запрос статистики

```sql
SELECT
  COUNT(DISTINCT o.ORDERID) as total_orders,
  COUNT(DISTINCT oi.ORDERITEMSID) as total_items,
  COUNT(DISTINCT g.ID) as total_materials,
  SUM(...) as total_quantity,
  SUM(itd.SAVINGCOST) as total_cost
FROM ORDERITEMS oi
JOIN ORDERS o ON o.ORDERID = oi.ORDERID
LEFT JOIN MODELS md ON md.ORDERITEMSID = oi.ORDERITEMSID
JOIN ITEMSDETAIL itd ON (itd.MODELNO = COALESCE(md.MODELNO,0) AND itd.ORDERITEMSID = oi.ORDERITEMSID)
JOIN STUFFS g ON (g.ID=itd.GOODSID)
LEFT JOIN RECALCGROUP rec ON rec.RECALCGROUPID=g.RECALCGROUPID
JOIN STUFFTYPES ggt ON (ggt.ID = g.STUFFTYPEID)
WHERE o.DELETED = 0
  AND [фильтры]
```

#### Запрос списка заказов

```sql
SELECT DISTINCT
  o.ORDERID,
  o.ORDERNO,
  o.DATECREATED,
  o.ORDERSTATUS,
  COUNT(DISTINCT oi.ORDERITEMSID) as items_count,
  COUNT(DISTINCT g.ID) as materials_count
FROM ORDERITEMS oi
JOIN ORDERS o ON o.ORDERID = oi.ORDERID
-- ... остальные JOIN'ы
WHERE o.DELETED = 0
  AND [фильтры]
GROUP BY o.ORDERID, o.ORDERNO, o.DATECREATED, o.ORDERSTATUS
ORDER BY o.DATECREATED DESC, o.ORDERNO
ROWS [пагинация]
```

#### Детальный запрос по заказу

```sql
SELECT
  oi.ORDERITEMSID,
  oi.NAME,
  g.MARKING,
  ggt.NAME as ITEM_DESC,
  g.NAME as ITEM_NAME,
  itd.WIDTH as W,
  itd.HEIGHT as H,
  itd.THICK as L,
  itd.QTY,
  itd.SAVINGCOST as ITEM_PRICE,
  -- ... остальные поля
FROM ORDERITEMS oi
JOIN ORDERS o ON o.ORDERID = oi.ORDERID
-- ... остальные JOIN'ы
WHERE o.ORDERID = ?
  AND o.DELETED = 0
  AND [фильтры материалов]
GROUP BY [все поля]
ORDER BY oi.ORDERITEMSID, g.MARKING
```

## Клиентская оптимизация

### 1. Кэширование деталей заказов

- Детали заказов загружаются только при первом раскрытии
- Результаты кэшируются в памяти для повторного использования
- Индикатор загрузки для лучшего UX

### 2. Улучшенная пагинация

- Уменьшен размер страницы с 100 до 50 заказов
- Кнопка "Загрузить еще" вместо традиционной пагинации
- Предотвращение дублирования заказов при загрузке

### 3. Расширенная статистика

- Отображение общего количества заказов, изделий, материалов
- Показ общего количества и стоимости материалов
- Статистика загружается мгновенно без ожидания

## Рекомендации по индексам

Создан файл `optimize_database.sql` с рекомендуемыми индексами:

### Критически важные индексы:

```sql
-- Основные фильтры заказов
CREATE INDEX IDX_ORDERS_MAIN_FILTERS ON ORDERS (DELETED, ORDERSTATUS, DATECREATED DESC);

-- Поиск по материалам
CREATE INDEX IDX_STUFFS_SEARCH ON STUFFS (STUFFTYPEID, NAME, MARKING);

-- Связи между таблицами
CREATE INDEX IDX_ITEMSDETAIL_MODEL_ORDER ON ITEMSDETAIL (MODELNO, ORDERITEMSID);
```

### Дополнительные индексы:

- Индексы для поиска по артикулу: `IDX_STUFFS_MARKING_SEARCH`
- Индексы для поиска по названию: `IDX_STUFFS_NAME_SEARCH`
- Составные индексы для частых запросов
