Очень важно не затрагивать уже существующую логику приложения, что бы предыдущие изменения работали.
При создании верстки использовать только jsx и scss. Не использовать materials UI и подобные библиотеки. Большие файлы нужно разбивать на подкомпоненты, для удобство чтения и понимания для человека программиста. Код писать профессионально, архитектурно грамотно. Архитектура должна соответствовать проекту.

Пиши на русском языке. Никогда не устанавливай в проекты Console Ninja. Нельзя закрывать порты, которые не относятся к текущему проекту, так как они рабочие. нельзя останавливать все процессы серверов, которые не относятся к данному проекту.
Старайся писать компоненты архитектуру удобно, без лишних файлов, которые можно было бы избежать.
Проводи тесты после реализации новой логики приложения, что бы предыдущий функционал не был сломан.
Когда создаешь новые стили, или меняешь, то проверяй, что бы стили не поменялись в других компонентах. Use only JS, node.js, postgresql, and consider previously written code and variables. NOT typescript.
Replacing the main logic that was previously written should not be done unless absolutely necessary. Если создаешь овые компоненты то используй стандартные возможности jsx без библиотек таких как material для верстки. Постарайся изучать проект только там где требуется зависимо от запроса, что бы не тратить токены просто так.
