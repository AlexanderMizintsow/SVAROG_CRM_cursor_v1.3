# 🔧 Альтернативное исправление фильтрации по датам

## ❌ Проблема

После первого исправления с `CAST(o.DATECREATED AS DATE)` проблема все еще остается:

- Диапазон **01-02 сентября** → 1 заказ
- Диапазон **01-05 сентября** → 1 заказ (но другой)

Это означает, что заказы созданы в разные дни, и логика фильтрации все еще работает некорректно.

## 🔍 Анализ

Проблема может быть в том, что:

1. **CAST в Firebird** работает не так, как ожидается
2. **Формат дат** передается неправильно
3. **Логика сравнения** все еще учитывает время

## ✅ Новое решение

### Подход с добавлением времени к датам

Вместо использования `CAST` будем явно добавлять время к датам:

**Было:**

```sql
CAST(o.DATECREATED AS DATE) >= ?
CAST(o.DATECREATED AS DATE) <= ?
```

**Стало:**

```sql
o.DATECREATED >= ?  -- где ? = '2025-09-01 00:00:00'
o.DATECREATED < ?   -- где ? = '2025-09-02 23:59:59'
```

### Логика работы

- **Начальная дата**: добавляем `00:00:00` (начало дня)
- **Конечная дата**: добавляем `23:59:59` (конец дня)
- **Оператор**: используем `<` вместо `<=` для конечной даты

## 🔧 Технические изменения

### Файл: `server/AW/utils/statisticsUtils.js`

```javascript
// Было
if (filters.startDate) {
  conditions.push('CAST(o.DATECREATED AS DATE) >= ?')
  params.push(filters.startDate)
}
if (filters.endDate) {
  conditions.push('CAST(o.DATECREATED AS DATE) <= ?')
  params.push(filters.endDate)
}

// Стало
if (filters.startDate) {
  conditions.push('o.DATECREATED >= ?')
  params.push(filters.startDate + ' 00:00:00')
}
if (filters.endDate) {
  conditions.push('o.DATECREATED < ?')
  params.push(filters.endDate + ' 23:59:59')
}
```

### Примеры работы

**Диапазон 01-02 сентября:**

```sql
WHERE o.DATECREATED >= '2025-09-01 00:00:00'
  AND o.DATECREATED < '2025-09-02 23:59:59'
```

Найдет заказы с 01.09.2025 00:00:00 по 02.09.2025 23:59:59

**Диапазон 01-05 сентября:**

```sql
WHERE o.DATECREATED >= '2025-09-01 00:00:00'
  AND o.DATECREATED < '2025-09-05 23:59:59'
```

Найдет заказы с 01.09.2025 00:00:00 по 05.09.2025 23:59:59

## 🎯 Ожидаемый результат

Теперь должно работать правильно:

✅ **Диапазон 01-02 сентября** → найдет все заказы за 01 и 02 сентября
✅ **Диапазон 01-05 сентября** → найдет все заказы за 01, 02, 03, 04, 05 сентября
✅ **Логичная зависимость** → больше диапазон = больше или равно результатов
✅ **Точное время** → учитывается весь день от 00:00:00 до 23:59:59

## 🔍 Отладка

С новым логированием в консоли будет видно:

1. **Входные фильтры** - какие даты передаются
2. **SQL запрос** - какой именно запрос выполняется
3. **Параметры запроса** - с какими значениями
4. **Найденные заказы** - номера и даты найденных заказов

Это поможет точно определить, в чем проблема.
