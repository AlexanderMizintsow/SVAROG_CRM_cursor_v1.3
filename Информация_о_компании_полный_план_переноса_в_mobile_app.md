# Информация о компании: полный план переноса в мобильное приложение

Документ фиксирует сценарий **`/info`** из `server/telegram_dealer_bot` для переноса в `apk/POZ` + `server/mobile_app` без изменения принципа интеграции с 1С (здесь 1С **не используется**).

---

## 1) Источники текущей логики

| Назначение | Файл |
|------------|------|
| Обработка команды | `server/telegram_dealer_bot/helpers/chatCommandHandler.js` — `case '/info':` |
| Справка по командам | `server/telegram_dealer_bot/helpers/helpMenu.js` — `usage: '/info'` |

---

## 2) Поведение в Telegram

1. Пользователь выбирает пункт «Информация о компании» (в меню помощи это команда **`/info`**).
2. Бот отправляет **одну строку** — URL: `https://poz-sar.com/about/details/1/`.
3. Вызывается **`handleCancel`**: сброс контекста диалога к состоянию после команды (как в других одношаговых командах).

**Интеграции:** нет БД, нет 1С, нет AW API.

---

## 3) Что перенести в POZ + `mobile_app`

| Элемент | Рекомендация |
|---------|----------------|
| Контент | Либо **WebView** / внешний браузер по тому же URL, либо **нативный экран «О компании»** с тем же текстом/структурой, если маркетинг захочет офлайн-режим. |
| API | Опционально: `GET /mobile/content/company-info` → `{ url }` или `{ html }`, чтобы менять ссылку без релиза клиента. |
| Авторизация | Достаточно проверки, что пользователь залогинен; привязка к компании для этой ветки не требуется. |

---

## 4) Паритет с ботом (чеклист)

- [ ] Пользователь по смыслу получает ту же «карточку» информации (ссылка или эквивалент).
- [ ] Нет прямых обращений к 1С с устройства.
- [ ] Ошибки сети при открытии URL обрабатываются понятным сообщением (дилеры по всей стране).
